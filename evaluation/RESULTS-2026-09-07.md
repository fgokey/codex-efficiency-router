# Independent quality and token evaluation — 2026-09-07

## Scope and overall conclusion

The expanded **offline evaluation did not fully pass**. Existing regression tests passed, but an additional boundary probe failed and one deliberately broken policy escaped the existing tests. Text-token counting also showed that loading every new reference can exceed the old core's instruction overhead.

This is not a live Astra/Sol/Terra/Luna coding-quality or billing benchmark. No model inference or model credentials were used. Production files and `main` were not modified by this evaluation.

## Finding 1 — same-lane delegation admission gap

An additional probe supplied an unresolved Sol-level task, current lane Sol, `current_sufficient=False`, `benefit_clear=False`, native routing available, and only Sol in the available lanes.

The expected outcome was `blocked` until a capability or concrete fresh-context/isolation benefit is established. The offline helper returned `delegate`.

This probe is an executable interpretation of the Skill's existing same-model delegation rule. It identifies a mismatch in `choose_dispatch`, not proof that a live Codex model already made that mistake. Repeating the same lane without a demonstrated benefit can create extra context and retries without resolving insufficiency.

Suggested correction: distinguish a genuine capability upgrade from same-lane contextual recovery; require an explicit justified recovery/isolation benefit for the latter. Preserve explicit user constraints and avoid silently weakening acceptance. No production patch was applied in this evaluation.

## Finding 2 — no-subagent test coverage gap

The `ignore_no_subagents` mutation removed the user opt-out from the helper's admission guard. Existing policy tests still passed.

This does **not** mean the shipped guard is absent. It means the tests do not reliably detect its removal. Existing opt-out checks can produce the expected local/blocked outcome because routing is unavailable by default, even when the actual opt-out guard is broken.

Suggested regression: set `no_subagents=True` together with `host_supports_routing=True`, an available requested model, and a task that would otherwise delegate. Confirm the shipped code respects the opt-out and that deleting the guard makes this test fail. Cover both sufficient and insufficient current-agent cases.

The other nine mutations were detected: always Astra, always Terra, ignored prerequisites, skipped cheap discriminating check, ignored explicit Astra override, ignored no-escalation, skipped benefit gate, unsafe unavailable-route fallback, and wrong mechanical lane. These ten hand-selected mutations are not comprehensive mutation coverage.

## Text-token results

Measured with OpenAI tiktoken **0.11.0**, using explicitly named reference encodings. These are exact raw-text counts under those encodings, not exact Astra billing. All four model-to-tokenizer lookups were UNKNOWN in the pinned package; no mapping was silently assumed.

| Loaded text | o200k_base tokens | cl100k_base tokens | o200k_base change versus old core |
| --- | ---: | ---: | ---: |
| v0.1 core | 2,511 | 2,541 | baseline |
| v0.2 core only | 1,354 | 1,359 | -46.08% |
| v0.2 core + dispatch reference | 2,122 | 2,126 | -15.49% |
| v0.2 core + both references | 2,793 | 2,805 | +11.23% |

Discovery description alone: 128 → 57 tokens under o200k_base; 130 → 56 under cl100k_base. These description counts are components of the text analysis, not additional values to add blindly to the core totals.

Per-role developer instruction text under o200k_base: Luna 163, Terra 162, Sol 199, Astra 249 tokens. These are not the full cost of spawning agents; host instructions, inherited context, tool schemas, task capsules, tool output and generated reasoning/output are excluded.

### Interpretation

The light path has a smaller instruction footprint. A delegated path loading dispatch still has less instruction text than the old core. But loading every reference makes this component about 11.2% larger than the old core. Therefore the previous core-size reduction must not be presented as guaranteed overall token savings.

Progressive disclosure needs to be observed in live traces. The added detail may protect quality on hard tasks, but it has a real text cost. Savings from using cheaper models or preventing retries could outweigh that cost; this experiment does not measure that tradeoff.

## What a real task-level comparison still requires

Use a logged-in Codex host with the actual Skill and role presets. Compare baseline and router on isolated copies of the same task/revision/environment, with independently fixed acceptance and multiple trials. Verify actual model/effort and which references loaded. Count all parent/child input, output, reasoning as defined by the host, cached input, failed attempts, verification and coordination; avoid double-counting cumulative usage. Measure start-to-accepted-completion wall-clock time separately.

A pass requires preserving the defined quality gate; lower token use does not compensate for failed behavior. These offline results are useful evidence about policy and overhead, not a claim of live quality equivalence, a subscription-quota conversion, or a measured task-level speedup.
