# Delegate without restarting the workflow

Establish authority, exclusive write scope and capacity first. Reuse a compatible owner at a safe boundary; wait when both writers are busy. Keep prior edits; no auto-revert.

Handoff only the goal, facts versus assumptions, revision/dirt, relevant files and rule paths, rationale/invariants, allowed scope, prohibitions, checks and retained attempts. Read required repository rules; critical gaps block affected work. Contrary evidence reopens decisions.

Create a worker with explicit role/effort and no inherited transcript. HOLD until current host model/effort/role/permission/owner is verified; then explicitly RELEASE the unit. UNKNOWN/MISMATCH blocks writes. Keep the same admitted executor for diagnosis, fixes, formatting, build configuration and targeted tests. Closed/unloaded/restarted workers need fresh binding and release; raw `resume_agent` cannot pin them.

For the registered dispatch boundary, Reader `assignment` prepares task-bearing messages. Verify script paths; consult `assignment --help` only when needed. Send exactly the checked prefix and body. With the custom host, use `prepare_agent_task` and `admitted_agent_task`; always pass returned `admitted_dispatch_arguments` so another recipient cannot inherit Sol61/high. The checked `CER execution` declaration conveys effects and existing permission, never grants authority.

Exact continue/status/stop controls reuse the current receipt, scope and binding without new work or a new worker. Added instructions require new admission. Bare control words are not receipts. Wait/interrupt/close remain separate controls. Policy denial stops equivalent replay until an authorized boundary change; never evade `approval=never`.

Astra uses permitted reads and saved evidence, never `write_stdin`. Executors own long commands/continuation. Strict Guard remains strict; unprotected hosted tools and unknown paths are disclosed, not certified. Custom-host installation is separate from Skill installation.

Parent reviews all roots, exact paths/status/diffs and prior dirt, then accepts integration. Native parent file-change attribution is optional unless required by the user; never fake a badge or edit for attribution. Binary copies, runtime configuration, destructive recovery and commit/push/deploy need separate user authority and exact destinations.
