# Evidence and completion

Before final, reconcile the original user objective, accepted scope, every remaining required item and current authority. CONTINUE while useful authorized diagnosis, delegation or implementation remains; child PASS or green local checks are not parent completion. COMPLETE requires current evidence for every requirement. BLOCKED requires the exact external missing resource, evidence, affected scope and required external action; finish unaffected work. STOP on explicit pause/cancel, scope change or actual system budget ceiling. Answer mid-task status briefly and continue; standalone questions end after answering. Never start unrequested monitoring or risky measurements.

Reuse unchanged loaded rules; fully read necessary new/changed rules. Verify physical paths/links. Released writers: authorized bounded native reads; Astra/readonly/unknown: guarded reads. Select sources/fields before emit; tool caps truncate. Store read_thread results; select required fields/ranges. Batch UTF-8; one aggregate budget including JSON, CRLF and framing (<=4KiB). Reader: verified Python `-I -B`, UTF-8 stdin. Check exit before parsing; retain successful results, errors and each cursor. Tests: each exit/counts/failure details. Read required ranges completely; continue missing pages rather than rereading files. Never slice full-file output, concatenate pages to evade limits or infer completion from truncation.

Review available work before waiting. Batch independent reads and merged worker waits. Prefer a supported native event wait; never finalize while required work remains. Inspect detail only on actionable change, failure or completion; after two unchanged snapshots back off. One saved-offset diagnostic delta is enough; do not repeat tails or nudges without new evidence. Optional `COORDINATION_JS` is an adapter, not proof of work. Code Mode: first-line `@exec` yield must cover the WHOLE wait. Continue yielded cells with sufficient supported yield; never start another wait cell. Reader `COORDINATION_QUIET_JS` combines at most two 50s waits under an advertised 120s yield; otherwise use one supported native wait. No status/admission/completion polling while unchanged.

Check platform/macros, consumers and lifecycle effects. Loss/eviction/coalescing must preserve effects or prove safe discard/replay/rebuild. Findings need source evidence or a requirement violation; distinguish hypotheses and preexisting hazards. Tests use real production behavior or explicitly labelled models; a green model or static score is not proof of end-to-end correctness. Never weaken assertions.

Attempts persist per task/unit/failure across all owners, models and compaction. A patch mismatch gets context/encoding/EOL inspection and one targeted repair. Exhaustion stops blind edits, not Astra diagnosis. Run required checks on final stable state; repeat only affected or failed checks. Unrun evidence is UNKNOWN; required gaps remain PARTIAL/BLOCKED. Parent: open the actual source/diff/result; assess caller/test applicability and blockers. Reject child reports and completion_check declarations alone; reuse checked evidence unless changed/disputed. Use `completion_check` only when provided by the host, beginning before appending requirements; then at changed requirements or final acceptance, not every wait. Count all parent/child work; cached input is a subset, and unavailable prices or usage remain UNKNOWN.
