# Completion and recovery

Reuse the execution contract. A substantial unit needs only: requirement ID | check/review evidence | applicable state | PASS/FAIL/UNKNOWN. Evidence is an observed command/result or reasoned review, not confidence. Read-only design can use explicit review criteria; no irrelevant build requirement.

PASS requires all outcomes and mandatory integration/review gates evidenced on relevant final state, with no blocking finding. PARTIAL leaves work/evidence outstanding; BLOCKED needs a prerequisite/decision. Optional disclosed risks may remain in PASS; required gaps cannot. Only authoritative scope changes create a new contract revision; retain the earlier gap, never let executors waive failed checks.

Compare requirements, plan and code before editing. Block only affected scopes; preserve independent progress. Revalidate relevant changed state, not the entire task. Matching HEAD is insufficient when dirty files, tests, dependencies or environment changed.

Use one parent-owned checkpoint only when needed/permitted; never overwrite another task's record. Keep IDs, contract, completed scope/evidence, state, active workers and failed approaches with remaining budget. No credentials. After recovery reconcile files and workers; reuse valid completed work, revalidate stale parts, reconcile unknown side effects before replay.

Attempts belong to task/unit/failure signature across agents and compaction. Renaming an error/worker cannot reset history. Exhaustion requires a new experiment/decision or explicitly justified bounded parent extension, never another blind patch. Unknown prior attempts require reconstruction, not a fresh budget.

Offline helpers test declared conditions only; they do not inspect real code or enforce Codex. Natural-language cases require actual user-run tasks and independent grading before any behavioral success claim.
