# Evidence-gated routing reference

Read only when the compact policy cannot resolve an escalation. Use task evidence, not a technology keyword or a universal numeric score.

## Three Astra prerequisites

1. Stronger reasoning can reduce the current uncertainty. Required facts, authority, and environment are sufficient for the decision being asked.
2. The unresolved decision is consequential, genuinely novel/deep, or has a demonstrated lower-lane capability failure.
3. A safe inexpensive experiment cannot settle it first. “Cheap” does not include destructive production trials.

Missing observability may itself require design reasoning: isolate the answerable instrumentation-design task from the unanswerable root-cause claim. Do not wait for impossible evidence, and do not pretend a hypothesis is established.

## General task shapes

| Shape | Astra-worthy question | Lower-lane counterexample |
| --- | --- | --- |
| Durable commitment | Compare viable public contracts, persistent formats, ownership or compatibility strategies with expensive reversal | Implement an approved contract |
| High-consequence ambiguity | Resolve an unclear trust, data-integrity, billing or production invariant | Apply an explicitly specified, strongly checked rule |
| Evidence arbitration | Reconcile credible contradictory observations or surviving causal hypotheses | Run a known discriminating test |
| Costly migration | Decide coexistence, rollout ordering, partial failure, rollback and recovery | Execute a verified migration on authorized fixtures |
| Novel mechanism | Design a new algorithm, protocol, state or scheduling model without adequate precedent | Adapt an established pattern with known constraints |
| Independent judgment | Resolve meaningful disagreement or review residual consequential risk not covered by deterministic checks | Repeat a routine completed review |
| Proven capability failure | A scoped Sol attempt cannot solve the remaining reasoning despite adequate specification, tools and evidence | A network timeout or missing dependency |

No compulsory Luna -> Terra -> Sol -> Astra ladder. Skip futile low-tier retries for obvious hard decisions. Conversely, a frozen migration implementation can use Terra; authorizing an irreversible live migration remains a separate permission boundary.

## Failure taxonomy

- Specification/authority: identify the precise missing decision; continue independent safe work. Never invent consequential requirements.
- Environment/tool: diagnose setup, permissions, dependency or flaky infrastructure with bounded recovery. Do not request stronger reasoning for a missing credential.
- Observability: add an appropriate test/trace or return UNKNOWN; stronger reasoning cannot certify unseen runtime behavior.
- Implementation: repair the specific coding mistake once on the same leaf, within scope.
- Capability: provide evidence, alternatives already rejected, attempt results and a precise question; promote to the minimum sufficient lane.

Two attempts without progress are a stopping budget, not proof of capability failure. New evidence can justify immediate escalation; a changed error alone is not progress.

## Phase changes and overrides

EXPLORE and DECIDE do not automatically imply Astra. EXECUTE does not automatically imply Luna. VERIFY may require senior judgment. At a meaningful phase change, assess remaining uncertainty rather than the task's original label.

Reopen a contract when requirements, relevant code, dependencies, test assumptions or evidence change. A forced model choice changes cost preferences only. A ban on delegation or escalation can leave work blocked; do not silently proceed with an insufficient model.

The Python reference policy tests these rules offline. It does not execute routing, and passing its cases does not prove that a live model obeys the Skill.
