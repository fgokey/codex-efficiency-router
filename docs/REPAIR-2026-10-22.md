# Execution-coherence repair, 2026-10-22

Base: main `5457e97d95d77f2dc17b6a869e4082c338b510f0`. This repair retains its deliberate host-mode and accounting changes. It does not silently replace a full installation with compat, change the parent model, or remove active protections.

## Scope

- Source closure: include exactly the documented `host/required-agent-admission.patch`, reject linked or missing required patches, never sweep a host checkout, binaries or private files into a ZIP.
- Shared dispatch contracts: Reader pair validation and canonical roles are used by spawn and recipient checks. Positive tests cover each shipped executor from HOLD through current binding, RELEASE and controls. Cheap executors still need simple low-risk work; Astra remains read-only and needs current complexity evidence.
- Continuation: exact continue/status/stop words reuse the admitted scope, body fingerprint, model/effort and policy. New work cannot hide in a control label. Current direct-parent ownership and archival state are rechecked. Bare words without a receipt remain rejected. No new worker or retry budget is created by a control. Dedicated native wait/cancel/close remain separate.
- Windows: honor CODEX_HOME, retain Unicode and spaces, accept UTF-8 BOM while rejecting duplicate JSON keys. Test CRLF fixtures are written as bytes to avoid Windows double newline conversion; the Reader must still preserve the actual bytes.
- Instructions: replace compressed protocol fragments with readable stage-specific rules, clear invocation boundaries and a smaller complete reference chain. Preserve ownership, two-writer limit, current evidence, retry history, Astra reasoning participation and authoritative permissions. Size limits and historical tokenizer baselines are unchanged.
- Mutation coverage: add causal positive/negative cases for failed fixed bindings and Ultra fallback, so earlier effort mismatches or unreachable branches cannot mask a deleted guard. Mutation targets and quality thresholds are not weakened.
- CI: use a physical temporary root on POSIX runners so `/var` aliases do not mask the behavior a fixture intends to test. Runtime symlink/reparse rejection remains unchanged. Windows uses its native temporary paths and launchers.

## Windows update

Use the checked `cer.ps1` launcher from the repository. Preserve the same scope, project and CODEX_HOME. Review dry-run first, reach a safe boundary, install, run static doctor, then reload Codex. Do not interrupt active writers or hot-replace a running host binary.

If native dispatch/write guards were separately registered, inspect and update each existing registration through `write_guard.py`/the guard launcher; re-review changed commands in `/hooks`. Do not automatically install a boundary merely because an older one is absent. New policy or bundle hashes invalidate old receipts and witness reports; obtain current evidence rather than relabelling them PASS.

The custom host still requires compatible native tools. This patch does not rebuild it. `prepare_agent_task`/`admitted_agent_task` are not invented ordinary tools. The Reader returns exact `admitted_dispatch_arguments` for that path, avoiding its default model/effort on assignments to cheaper executors. Older host versions may reject the new control protocol: stop the affected operation rather than replaying through a prohibited route. No new database ledger, daemon, recursive model process or auth change is introduced.

## Validation interpretation

Repository CI is the integrated test environment for this repair. Verify the exact head commit and all jobs, including extracted-artifact tests; a passing source suite alone is insufficient. Targeted local checks on reconstructed functions are not a complete clone or Windows runtime test.

Existing executable policy, mutation, ownership and lifecycle checks remain. Wording-sentinel tests are updated for rewritten sentences; they check retention of the same boundaries, not model obedience. Native-host and real-model work is not run by CI. The live behavior corpus remains explicitly unrun. Do not infer business-task quality, a speedup, pricing or subscription savings from text counts, finite mock-host paths, or a green workflow.

## Remaining product boundaries

The optional host adapter still uses a pinned SQLite schema; it is not a universal identity API. Strict guard coverage still needs native acceptance. Current high-effort preferences are not retuned without paired workload evidence. Wider Reader pages, host-level persistent admission, and removing the custom-host dependency are not claimed by this corrective repair. These need independently scoped work rather than another implicit runtime layer.
