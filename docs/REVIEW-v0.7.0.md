# v0.7.0 优化计划评审与候选实现边界

## 结论

计划主线合理：先解决安装与运行状态可见性、版本漂移和证据缺口，再讨论性能。
保留“软策略 / 已注册 / 当前范围已验证”区分、显式授权、现有改动保护、有限 batch、
按真实模型分开计价和固定发布锚点。不能因为静态测试多，就宣称现场已受保护。

本次据此修改源码，不重写既有路由/质量规则；候选版是 v0.7.0-rc.1，而非假装已经
达到正式 v0.7.0 的现场、跨平台 CI 和发布门槛。

## 需要收紧的五处

1. **模型身份：** 旧 Guard 曾把执行模型前缀也当作可写身份。现改为审查过的精确 ID。
   未知后缀/快照不自动放行；工具输入伪造 model 不能覆盖宿主字段。Astra 根/叶都保持
   只读，没有 Write Lease。两写者上限仍是 Router 策略，不伪装成 Hook 原子锁。
2. **现场证明：** 无哨兵文件也可能是模型没调用工具或 sandbox 先拦截，不能独立 PASS。
   必须观察当前 native Hook 拒绝、模型身份、读取/协调成功及执行者写入成功。
   本 RC 提供显式操作者见证流程，不编造缺失的宿主机器证明接口。
3. **状态时效：** 保存 PASS 不是永久通行证。绑定配置字节、脚本摘要、Skill 字节、
   作用域、当前 Codex 版本和两小时有效期；变化后 STALE，未知当前版本为 UNKNOWN。
   磁盘安装版本不能当作当前任务已加载版本，握手也不自行猜测。
4. **batch 范围：** 保留原单文件 search，修正计划中目录 search 示例可能暗示的扩展。
   16 操作、16 KiB 输入、16 MiB 合计文件字节、128 KiB 合计输出；路径逐个预检。
   Git 内部扫描/恶意文件系统竞态不是这里能保证的资源或安全边界。
5. **发布与收益：** Plugin schema 通过不等于原生发现/信任已通过；三组费用数据结构
   通过也不等于实际账单降低。准确标出候选包、离线微基准与未完成的现场门槛。

## 保留的用户约束

固定模式与 automatic low 设置不因升级改变。Astra 必须参与复杂诊断和失败归因，
不是旁观者；具体写入、构建和有副作用验证仍由授权执行者处理。不给执行模型越过
宿主沙箱/其他 Hook 的额外许可。已有修改由兼容所有者独立复核接管，不自动回滚。
普通 Skill 安装不注册 Hook，不更改用户 AGENTS.md、config.toml 或认证。

安装失败仅回滚仍匹配本事务写入内容的自身文件；同期外部修改保留并提示。所有
配置变更需要显式 install/update/remove，status/doctor 不创建追踪文件或后台进程。
