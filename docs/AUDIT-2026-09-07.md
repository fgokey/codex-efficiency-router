# v0.2.0 audit — 2026-09-07

## Scope and baseline

Reviewed the published v0.1.0 source at commit `e92d89a79c05985980420a0bfd6a51baec93ba81`, tree `5f5d22eb938e340c26e918a5390ca4a3cef68ad5`. The available complete source archive was verified against that Git tree before editing. The baseline had four unittest methods and eighteen routing scenarios. Its successful CI did not establish live model behavior or safe uninstall semantics.

The audit used current [OpenAI documentation and primary industry engineering sources](PRIOR-ART.md). It assessed correctness, actual versus requested model identity, token/context overhead, delegation economics, failure escalation, installation ownership, verification, documentation and evidence quality.

## Findings and changes

| Finding | v0.2.0 correction | Evidence category |
| --- | --- | --- |
| Long always-loaded-on-activation policy duplicated details | Smaller core plus two packaged progressive references | Byte measurement and packaging tests |
| Prose called for cheap falsification, but offline rules did not implement it | Explicit prerequisite, authority, reasoning-bound and discriminating-check gates | Scenario/property tests |
| Disabling subagents could erase the capability recommendation | Separate recommendation from dispatch admission and safe fallback | Dispatch tests |
| Retry count could be treated as model insufficiency | Qualified capability failure, not raw attempts | Negative regression cases |
| Forced downgrade could waste startup/context on tiny tails | Reevaluate capability and benefit before handoff | Policy contract; live benefit unmeasured |
| Role files and spawn requests could disagree | Document file precedence and distinguish requested from observed execution | Official-doc review; live behavior unverified |
| Sol leaf could delegate recursively; maximum-effort text was inconsistent | All leaves bounded; no recursive spawn or automatic max/Ultra | Shipped instruction review |
| Filename-only overwrite/removal lacked ownership | Hash manifest, unowned-collision refusal, edit detection and explicit legacy adoption | Lifecycle tests |
| Ordinary write failure could leave a partial install | Backup, per-file atomic replacement and tested rollback | Injected-failure tests; not power-loss atomic |
| Removal and recovery were under-specified | Owned-only removal, untracked-file preservation, guarded restore and both README command sets | Lifecycle and CLI tests |
| Doctor could be read as a runtime success certificate | STATIC PASS/FAIL and explicit live NOT VERIFIED; optional saved model/list validation | Structural/catalog tests |
| No comparable real-world efficiency evidence | Optional descriptive paired-run comparator rejects mismatched/unknown data | Synthetic comparator tests; no live benchmark |

## Reproducible local validation

```sh
python3 -m unittest discover -s tests -v
python3 scripts/doctor.py --source-tree .
python3 -m compileall -q scripts tests
git diff --check
```

At the audit checkpoint, **60 unittest methods** pass locally, including **36 routing scenarios** plus combinatorial negative-gate checks. Tests include real v0.1 fixture adoption, CRLF compatibility, user/project paths, customization preservation, collisions, dry-run, rollback, uninstall/restore, malformed manifests, catalog validation, CLI smoke and documentation link targets.

The core `SKILL.md` changes from **13,264 to 7,206 UTF-8 bytes**, a **45.67% reduction in core instruction bytes**. This is not tokenizer output or task-level token/cost/latency savings. Details moved into references may still load when relevant. The core retains required acceptance and evidence rules.

CI is configured for Ubuntu, Windows and macOS with Python 3.11 and 3.13. The workflow results associated with the published commit, not this document, are the authority on remote platform pass/fail. A Linux-only local test does not prove Windows/macOS execution.

## What is deliberately not claimed

No live Codex executable/model credentials were available to this audit environment. Consequently actual Skill trigger accuracy, native child dispatch, model/effort selection, permission precedence and Astra/Luna/Terra/Sol coding quality were not exercised. The installer and static tests do not spend model tokens.

No real paired task benchmark establishes a total-token reduction, speedup or non-inferiority margin. The presets remain conservative rather than being lowered on speculation. `scripts/compare_runs.py` supplies measurement hygiene, not a synthetic result presented as production evidence. A `no_observed_regression` sample may contain failures and is not a rollout certificate.

## Next acceptance layer

On the intended Codex host, verify role discovery and actual runtime metadata with a small read-only task, then run representative repeated paired tasks with fixed acceptance and full parent/child/retry accounting. Review critical regressions before considering savings. Follow [benchmarking](BENCHMARKING.md); do not automatically retune based on one successful run.
